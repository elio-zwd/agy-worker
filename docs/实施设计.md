# Codex GPT 经 MCP 调度 AGY 的本地部署实施文档

> 这是完整目标设计，包含尚未实现的阶段。2026-09-08 的实际安装能力与限制以仓库 README.md、schemas/ 和 docs/部署验收.md 为准；系统级隔离、Android 操作、源码写入授权尚未启用。

> 2026-09-09 增补：实现 `agy_capabilities` 以及 `agy://capabilities`、`agy://workspaces` 两个只读资源；所有已登记 Git 仓库支持经 common-dir 与 Git worktree 清单验证的 `workspace_path`。v0.3 又将 Codex stdio MCP 与 Runtime 生命周期拆开：每个 Codex 客户端使用一次性 Bridge，所有 Bridge 共用一个常驻 Controller 和唯一 Runtime。

版本 1.0　编制日期 2026年9月8日　目标环境 Windows 10 x64

面向执行本地部署的 AI 与项目维护者。本文件是实施规格，要求实现 Codex/GPT → MCP → AGY Worker Runtime 的完整闭环。Codex 负责总控、判断、源码分析与核心修改；AGY 承接高上下文、高噪声的执行、观察和资料整理任务。首个交付必须让 Codex 派发一次编译、收到结构化错误摘要、读取证据片段，并在 Codex 修复后再次编译。

本文中的 MCP 工具名、配置键、状态码及结果结构是本项目拟实现的接口，不代表 AGY 已自带这些接口。AGY 命令行参数依据本机帮助输出与已核对的 AionCore 源码；浏览器、Android 等能力需要另行接入执行适配器。部署不等于离线推理：AGY 使用的模型服务可能在云端，输入日志和图片前必须遵循任务数据范围。

## 1 架构与职责

```text
Codex / GPT
  总控  判断  源码分析  核心修改
       ↓ 任务目标与授权       ↑ 摘要与证据引用
stdio Bridge（可有多个）
  MCP 协议  参数校验  自动发现/拉起 Controller
       ↓ 认证的 localhost IPC
常驻 Controller / 唯一 Worker Runtime
  策略判定  AGY 进程管理  会话绑定  artifact 仓库
       ↓                     ↑
AGY 每轮独立进程 → 私有执行 Broker → 各任务适配器
                         build / log / browser
                         android-ui / vision / shell
```

stdio Bridge 不持有 SQLite、任务状态、线程池、令牌或 AGY 子进程。Controller 是唯一 Runtime 所有者并保留 `runtime.lock`；私有执行 Broker 仍是 AGY 的工具入口，执行侧每次调用都检查有效授权。Codex 只看到任务级工具，不看到 click、swipe、tap 等低层工具；这些操作留在 AGY 与适配器内部。

Bridge 启动时先读取 `data/controller.json` 并执行带随机凭据的 health check。Controller 不存在时，Bridge 通过 Windows WMI 在 MCP SDK 创建的 Job Object 之外隐藏启动 `pythonw -m agy_worker.controller`；并发首次连接由 `controller-launch.lock` 协调，只有一个进程取得 Runtime 锁。元数据中的 PID 和 endpoint 不能单独作为存活依据，必须通过 health check，协议版本不一致时明确拒绝。Bridge 退出不调用 Runtime.close；Controller 只在显式停止或自身退出时关闭。

Controller 继续使用单任务执行槽。多 Codex 对话解决的是客户端生命周期与共享状态，不意味着 AGY 并行执行；后续若增加并行，需要另行设计 workspace、浏览器、ADB 和构建工具资源锁。

| 任务 | AGY 的职责 | Codex 的职责 |
| --- | --- | --- |
| 编译与测试 | 执行命令，采集退出码，提取失败项和原文 | 分析原因，修改源码，决定重试 |
| 浏览器 | 按目标打开页面、读取、点击、填表、收集证据 | 决定目的、可写范围及业务结论 |
| Android APP | 指定设备上操作 UI，截图，采集 UI tree 与 Logcat | 判断缺陷，修改应用实现 |
| 图片 | OCR、界面描述、差异分析、位置标注 | 判断设计与代码如何调整 |
| 大日志 | 流式读取、过滤、去重、统计，保留证据定位 | 根因分析与修复决策 |
| shell 杂活 | 执行已授权的命令模板和批量整理 | 决定范围，审批源码写入 |

编译任务强制 analysis_level=extract_only：允许提取和分类 error、warning，不允许推测根因、推荐修复或自动改代码。视觉任务可以使用 analysis_level=visual_analysis，允许就图像本身分析；这不授予源码分析或源码写入权限。AGY 不得因为“这样才能完成任务”自行扩大权限。

Codex 的典型流程是 worker → status → artifact_read → 自行分析与修改 → continue。任务失败必须带证据返回；AGY 不在后台无限循环修复，也不自主派生无限子代理。

## 2 技术选择与实施边界

建议使用 Python 3.12 x64、官方 MCP Python SDK、Pydantic、标准库 asyncio 与 sqlite3，实现单机 Runtime；使用成熟的 Windows API 封装管理 Job Object。先检查目标项目现有依赖与版本；能复用则复用，不再引入第二套协议或进程框架。依赖须锁版本，安装脚本必须在 Windows 10 x64 实测。

浏览器优先采用 Playwright 的内部适配器；Android 先用 Android SDK Platform Tools 的 adb，再按需要增加 Appium。图像先走 AGY 实际可用的视觉能力，OCR 或转换仅在缺口明确时加依赖。不要假设安装 AGY 就已经具备浏览器控制、手机控制或图片输入链路。

官方 Playwright 当前系统要求列出 Windows 11 及以上桌面系统。Windows 10 宿主不应被宣称处于其当前支持范围。建议将浏览器适配器部署到本地、受支持的 Linux 虚拟机，经认证的私有通道调用；宿主上的 MCP、AGY 调度与脚本仍按 Win10 实现。若已有经过验证的 Win10 浏览器执行环境，可固定其受测版本，但必须记录维护限制，不自动回退旧版本。[S6]

本阶段不引入 Electron、AionUi UI、完整 AionCore 服务、ACP 桥或远程公网 MCP。AionCore 用于参考 direct-CLI、流解析与 hook 机制。源码引用或移植前核对 Apache 2.0 许可及 NOTICE，保留归属，不直接复制其全自动权限配置。

## 3 AGY direct CLI 集成

### 3.1 已核对的行为

核对的 AionCore 提交为 6effc3b11c6740ce496657516aa96c9b812d1be9。重点文件为 crates/aionui-session/src/backend/antigravity 下的 argv.rs、wire.rs、conn.rs、translate.rs，以及 crates/aionui-ai-agent/src/antigravity_hook.rs。[S1]

argv.rs 与 conn.rs 使用一个 turn 一个进程，通过 --conversation 恢复上下文。新会话使用 --new-project；workspace 同时落实为进程 cwd 与 --add-dir。wire.rs 解析 event 为 init、step_update、result 的 NDJSON 包；init 的 conversation_id 可能在外层 envelope。不能直接套用其他 CLI 的 type 字段解析器。

本机 agy.exe --help 已确认 -p、--output-format stream-json、--conversation、--new-project、--add-dir、--print-timeout、--model 和 --mode。mode 列出的值为 accept-edits 与 plan；不要把 AionUi 的 default、yolo 当作 AGY 参数。帮助还列出 --sandbox、--json-schema、--input-format 与 --effort，但本方案不依赖它们，也不把 --sandbox 视作已验证的完整安全隔离。

本次没有调用模型执行真实任务或验证登录、hook 拒绝、图片输入。部署时必须记录 agy.exe 路径、文件版本或 SHA256、帮助输出、真实事件样本与模型列表。帮助说明支持参数，不等于相应安全行为已通过实测。

### 3.2 参数构造

以下是参数数组的设计示例，由进程 API 传入；不能拼接成一段 shell 命令。workspace 必须来自服务器登记的工作区映射。

```json
{
  "executable": "C:/Users/<用户>/AppData/Local/agy/bin/agy.exe",
  "cwd": "C:/agy-data/workspaces/demo/task-001",
  "argv": [
    "-p", "<受控任务提示词>",
    "--output-format", "stream-json",
    "--print-timeout", "20m",
    "--new-project",
    "--add-dir", "C:/agy-data/workspaces/demo/task-001"
  ]
}
```

续会话时删除 --new-project，增加 --conversation 与 Runtime 保存的 conversation_id。禁止使用隐式“继续最近会话”的 --continue，以免串项目。model 只接受 agy models 返回的完整 ID；显式指定模型后核对 init.model，不匹配时停止，不能悄悄换模型。mode 若省略就不传；plan 不等于文件系统只读，accept-edits 不等于得到源码修改授权。

AionCore 为 headless 工具调用加入 --dangerously-skip-permissions，并依赖自己的 PreToolUse hook 再做权限控制。默认不能照搬这个参数。部署探针应先验证不带该参数的授权动作是否可执行；若 AGY 拒绝，返回 permission_unavailable。只有操作系统隔离、私有 Broker 和拒绝测试全部通过后，才能在受保护的启动配置中打开它，不能由任务请求设置。[S1]

尤其注意：conn.rs 记录 AGY 1.1.9 的 hook 约 30 秒未返回时可能继续执行。因此 hook 超时不是可靠拒绝。Runtime hook 最迟 5 秒返回明确 deny；监测异常时终止任务。即使 hook 丢失或超时，也必须由 OS 隔离与 Broker 阻断真实资源访问。不要把 5 秒响应目标误当作消除了 fail-open 风险。

### 3.3 流解析与退出判定

stdout 和 stderr 独立、并发、持续排空，原始字节先落盘。采用增量 UTF-8 解码和换行缓冲，处理半行、CRLF、截断、超长行。非 JSON 行与未知事件保留到 raw，不让解析器崩溃；缺少关键终态时标记 protocol_error，不能因为退出码为 0 就判断任务成功。单行大小上限建议 1 MiB，溢出保存原始证据并给出异常标记。

区分三层结果：AGY 进程退出、AGY result.status、实际 build/test 等目标操作结果。AGY 成功描述“编译失败”时，AGY 自身可以成功退出，但任务仍是 failed。实际操作退出码由 Broker 捕获，不能只信模型文字。最终摘要优先使用完整 result.response；delta 仅供进度使用。原始终态缺失、相互矛盾或 artifact 未能持久化，都不报 succeeded。

会话绑定保存 session_id、conversation_id、workspace_id、规范化 cwd、AGY 身份、模型、策略版本和创建时间。conversation_id 由 Runtime 管理，不允许客户端任意指定别人的 ID。相同会话只运行一轮；工作区写任务、同一浏览器 profile、同一 Android 设备也要互斥。

## 4 方案 B 按任务授权

### 4.1 权限定义

有效权限由服务器策略与 Codex 本次明确请求取交集。超出策略直接拒绝并列出原因，禁止悄悄降低权限后继续做出不完整结果。未填写的权限均为 false 或空集合。授权是一轮任务的能力范围，不能由网页、日志、仓库文件、AGY 回答或“用户已同意”的自然语言声明替代。

| 能力 | 允许范围 | 额外限制 |
| --- | --- | --- |
| browser | 指定 origin 的读取或页面写操作 | 读写分开，限制重定向与下载 |
| android-ui | 指定 serial 和 package 的观察与交互 | 安装、清数据、卸载须独立动作授权 |
| build | 指定 command_id 的构建命令 | 仅批准的源码读取和产物目录写入 |
| log | 指定 artifact 或日志源的读取清洗 | 不能顺带读取其他项目、凭据文件 |
| vision | 指定图片的 OCR 与视觉分析 | 图片为不可信输入，结论带位置与置信信息 |
| shell | 精确命令模板、参数与 cwd | 默认关闭，不开放任意命令字符串 |
| code_write | 指定工作区、文件范围、用途和期限 | 默认 false，不包含提交、推送或合并 |

源码包括业务代码、测试、构建脚本、依赖清单和锁文件；这些都不是普通“构建输出”。build 可以写 build、.gradle、临时目录与独立缓存，但不能因此改 build.gradle、package.json 或测试期望值。生成源代码应放在明确的生成目录；若工具必须改源文件，先返回所需范围，由 Codex 修改或明确授权。

browser 的“写”是页面业务状态变化，与 code_write 无关。发消息、付款、删除业务数据等不可逆或对外行为须在任务中已有明确授权；普通浏览器交互授权不自动涵盖这些动作。Android 使用同样原则，且不能越过指定设备和包名。

### 4.2 强制执行

使用独立标准用户或本地 VM 运行 AGY；Runtime 策略、审计、授权记录和 hook 文件由控制账户持有，AGY 不可改写。源文件对 Worker 只读，仅输出目录可写。AGY 不继承控制用户的 HOME、SSH、浏览器主 profile、云密钥、项目外目录与额外 MCP 配置。

MVP 的独立低权限账户至少执行路径 ACL、源码写入阻断及命令白名单。要宣称 browser/android/shell 全面按任务强制隔离，必须使用实际受测的进程与网络限制；对任意 AGY 原生 shell、原生网络工具和间接工具调用进行阻断。如果无法验证原生工具不会绕过 Broker，该能力保持 disabled，不以提示词限制冒充已实现权限。

Broker 可部署在隔离边界外，通过每轮短期 token 识别任务，token 只允许使用该轮能力。AGY 调用私有工具如 execute_build、read_log_chunk、browser_task_step；Broker 对每次操作重新检查工作区、资源、参数及期限。内层工具不注册给 Codex。token 不能授予新增权限，Worker 不能访问外层 MCP 管理接口。

源码写授权仅从可信 Codex MCP 调用接收结构化 code_write=true、write_paths、reason 与本轮期限。Runtime 生成审计 grant_id；不用“approval_id”字符串作为唯一证明。授权通过后仅给指定隔离副本的文件写权限，任务结束撤销。续轮默认重置 code_write=false，需要再次明确给出范围；其他能力可显式复用上一轮权限，但仍校验当前策略。

所有路径按 Windows 规则规范化并校验最终对象，阻断 ..、绝对路径覆盖、UNC、设备路径、NTFS ADS、junction、symlink 与大小写绕过。至少禁止工作区中的重解析点；文件打开与执行前再次检查，避免校验后替换。后置 Git diff 是侦测手段，不能替代预先拒绝写入。

## 5 MCP API 规格

### 5.1 公共约定

使用官方 SDK 实现 stdio MCP。stdout 只写 MCP 协议消息，运行日志走 stderr 或文件。SDK 负责协议握手与消息编码；Bridge 与 Controller 之间使用带协议版本和随机 Bearer 凭据的本机 HTTP JSON 通道。六个公开工具都有严格输入 schema，拒绝未知字段，schema_version 固定为 1；本项目不保留旧接口兼容层。[S2]

工具调用采用提交后查询模式，agy_worker 与 agy_continue 应在 2 秒内返回 queued/running，不把长构建挂在一个 MCP 请求中。默认每个 Runtime 并发 1，后续按资源锁扩展。任务调用必须绑定 MCP 控制实例标识，禁止跨控制实例读取或取消任务。

| 工具 | 核心输入 | 核心输出 |
| --- | --- | --- |
| agy_worker | request_id、workspace_id、kind、objective、permissions、limits、inputs | task_id、session_id、status、revision |
| agy_continue | request_id、session_id、expected_turn、objective、permissions、inputs | 新 task_id、turn、status、revision |
| agy_status | task_id、after_revision 可选、wait_ms 可选 | status、revision、进度摘要、终态 result |
| agy_cancel | task_id、reason | cancelling 或已存在的终态 |
| agy_artifact_read | task_id、artifact_id、view、范围或 cursor | 片段或图像、证据位置、截断与下一游标 |

### 5.2 各接口的约束

agy_worker 的 kind 枚举为 build、test、browser、android-ui、vision、log、shell、composite。composite 必须显式列出各能力，不推断联合权限。inputs 只引用登记的资源 ID 或已授权 artifact；不允许任意宿主路径。limits 包含 total_timeout_sec、summary_max_bytes 与 artifact_max_bytes，实际值不能超过服务器上限。

request_id 用于幂等：同一个控制实例内，相同 request_id 与相同请求体返回原任务；相同 ID 不同内容返回 idempotency_conflict。必须先持久化请求再启动进程，避免网络重试重复执行有副作用的操作。

agy_continue 只允许已结束且有有效 conversation_id 的会话，并核对 expected_turn。上一轮仍运行时返回 session_busy。一次续轮产生新的 task_id，旧 artifact 不覆盖。工作区、身份、模型或权限安全级别发生不允许的变化时，新建会话，不能把旧历史当成权限依据。源码更新要记录新的输入快照及 diff 摘要，避免 AGY 按过时状态执行。

agy_status 默认立即返回；wait_ms 最多 25000，after_revision 支持等待状态变化。revision 是服务器单调递增版本。终态结果默认只含有限摘要及 artifact 清单，不自动附加所有日志。返回 updated_at 与 last_activity_at，进度百分比没有证据时用 null。

agy_cancel 幂等。终态任务不改状态；运行任务先转 cancelling，再停止 AGY 及本任务执行进程，撤销 token、释放资源锁、保存部分结果。仅提交取消请求不能立刻声称已取消成功。

agy_artifact_read 的 view 枚举为 metadata、text、image。text 支持一基行号 start_line/line_count 或不透明 cursor，两者互斥，默认最多 200 行及 64 KiB；返回 next_cursor、truncated 和实际行范围。image 返回 MCP image content 或该客户端可读取的授权 resource，不将整张图的 base64 塞进文本摘要。二进制日志先读取 metadata；大图派生缩略图或裁剪图，记录来源、缩放与坐标映射。

错误码至少包括 invalid_request、permission_denied、permission_unavailable、workspace_mismatch、session_busy、stale_turn、idempotency_conflict、auth_required、dependency_missing、protocol_error、artifact_not_found、artifact_expired、quota_exceeded 与 runtime_error。错误中禁止包含 token 和完整敏感参数。

## 6 任务状态与故障处理

状态流为 queued → running → succeeded 或 failed；运行中可转 cancelling → cancelled，超时为 timed_out。启动前授权不满足为 rejected；Runtime 重启后无法可靠恢复的运行任务记为 interrupted。失败编译属于 failed，而错误采集可以在 result 中标记 collection_status=complete。

状态在 SQLite 事务中更新，result.json 使用临时文件加原子替换发布。result.json 与 manifest 完整持久化后才发布终态。若磁盘满，至少在任务库记录 artifact_write_failed 和已保存清单。重启不自动重做浏览器提交、安装或其他有副作用的任务；先报告 interrupted，由 Codex 决定下一步。

timeout 分三类：AGY CLI 的 print-timeout、Runtime 整轮硬上限、具体适配器操作超时。总超时建议 build/test 1200 秒、browser/android 300 秒、vision/log 180 秒，可在策略范围内调整。CLI 上限略小于整轮上限，预留保存证据与清理时间。长构建无输出不能单凭静默判断挂死，应结合进程活动和适配器心跳；整轮硬上限始终有效。

Windows 使用 Job Object 管理任务进程，启用 KILL_ON_JOB_CLOSE，并在进程恢复运行前完成归属。AGY 原生后台服务、已存在的 Gradle daemon 或浏览器服务可能不在该 Job 中，必须通过适配器的任务句柄停止。构建优先 --no-daemon；不用按进程名 kill 全部 java.exe、adb.exe、chrome.exe 或 agy.exe。Job Object 是生命周期管理，不是完整安全沙箱。[S4]

取消时先阻止新工具调用，再给执行器最多 5 秒清理时间，随后终止所属 Job。保存 stdout/stderr、最后 UI 状态及 termination_reason；不能依赖 AGY 一定发出 result。取消的副作用不可自动回滚，应列出已完成动作与 remaining_effects。失效会话不能透明另开会话伪装续接成功。

## 7 分层结果与 artifact 仓库

采用三层结果：L0 是提交与状态回执；L1 是 Codex 默认读取的结构化摘要；L2 是完整证据仓库，按需取片段。L1 默认最多 16 KiB，建议最多 20 条主要错误，完整错误清单另存 errors.json。返回 total_errors、returned_errors、deduplicated_count、truncated，防止把摘要截断误认为只有这些错误。

每轮保存 AGY stdout.ndjson、stderr.log、实际 command stdout/stderr、脱敏可读日志、错误与警告清单、result.json、manifest.json、permissions.json、audit.ndjson；按任务保存 screenshot、UI tree、DOM、console、network 元数据和构建产物。保存 raw 不等于默认授权 Codex 或云端模型读取 raw 的全部内容。

manifest 每项包含 artifact_id、相对路径、媒体类型、字节数、SHA256、来源操作 ID、创建时间、敏感等级、完整性与行数。artifact_id 由 Runtime 生成，客户端不能把路径当 ID。证据引用使用 artifact_id 加行号、时间区间、页面节点或图像 bbox，所有定位绑定具体 artifact 哈希。

构建原始字节保留不变，同时生成 UTF-8 标准化文本用于稳定行号。原始编码未知时标注 encoding_unknown，不无声丢失字符。清洗中保留 exact message、首次与末次出现位置和计数；可按“文件、行列、任务、原文”去重，不把不同位置的错误强行合并。Logcat 保留时间、PID、TID、tag 和级别；错误上下文默认前后各 10 行。

Worker 只能向 staging 写候选文件；控制侧验证大小、类型、路径及摘要引用后移入只读最终仓库。Runtime 根据实际执行记录生成状态与退出码；模型生成的 JSON 只作为待校验的摘要，不得覆盖审计、manifest 或命令结果。无法生成合法摘要时返回 summary_invalid 和 raw 引用，不让模型无限重试。

保留策略建议 raw 7 天、脱敏摘要及一般证据 30 天、审计 90 天；任务可在策略内延长。运行任务和显式 pin 的证据不清理。默认任务 artifact 配额 512 MiB、总仓库 10 GiB；临近上限预警，达到上限停止采集并标记不完整，不悄悄丢弃错误。清理后保留 tombstone，读取返回 artifact_expired。轮转目录清理必须校验绝对路径归属。

凭据、Cookie、Authorization、签名 URL、个人数据和输入密码在回传视图中脱敏；敏感 raw 用 ACL 限制并可按需加密。network 默认保存 URL 的脱敏视图、状态码、时间与必要 header，不默认存全部请求体、响应体或 HAR。OCR 与截图可能泄露账户内容，执行前限制页面和区域。日志留在本机不意味着模型没有看到它；送入 AGY 的材料也受数据授权控制。

## 10 各类任务的执行规格

### 10.1 浏览器

任务示例：“在测试站点完成登录和设置页巡检，允许填写测试账号与修改显示语言，返回每步结果和截图。”inputs 指定 origin、测试资源 ID 和成功判据；权限限定 read、interact 及允许的业务动作，不包含任意站点与账户操作。

Playwright 运行在独立 browser context/profile，低层点击、等待、输入只暴露给 AGY。Broker 检查导航、iframe、弹窗、重定向、上传和下载目标；通过网络策略限制未授权访问。跨域依赖显式登记，不能发现页面加载不全就放开全网。保存前后截图、关键 DOM/可访问性树、console 与脱敏 network 元数据。UI 返回成功提示不等于服务端状态已改变，必要时再读取目标状态核验。

### 10.2 Android 与手机 APP

先检测 adb devices 的 authorized/online 状态；多设备时 serial 必填，绝不自动选第一个。所有命令带 -s 指定设备。任务示例：“在测试机 DEVICE_SERIAL 的 com.example.demo 中打开角色页，进入详情并返回，收集截图、UI tree 与这一时间段 Logcat，不清数据、不安装应用。”[S5]

包名、Activity、操作时限和停止条件由任务定义。Appium 或 adb 适配器负责点击、输入、等待和截图；坐标操作附屏幕尺寸、旋转方向和截图证据。UI tree 不可用的游戏、Canvas 或 WebView 页面，标注观察限制，视觉定位仍受任务权限约束。Logcat 尽量按进程和时间窗筛选，应用重启后重新捕获 PID。不得清空全局 Logcat 来简化处理。

安装 APK、卸载、pm clear、权限变更、重启设备分别授权；普通 android-ui 不包含任意 adb shell。MVP 手机目标是 Android；iOS 需要额外平台与工具链，本路线不承诺其支持。

### 10.3 视觉分析

任务示例：“比较两张角色页截图，列出文字遮挡、对齐和颜色差异，给出 bbox 和证据图，不分析实现代码。”inputs 指定 image artifact ID，analysis_level=visual_analysis。部署前用已知图片验证真实图像输入，不允许把文件名发给模型就声称已经看图。

输出 observations，每条含 observation_type、描述、image_id、bbox、坐标单位和 confidence 或 uncertainty。bbox 使用原图像素坐标；经过缩放需换算回原图。文字读取与视觉推断分开，模糊文字标记不确定。必要时让 Codex 按需取原图或局部裁剪复核，不能只返回无证据结论。

### 10.4 构建与测试

Android 使用固定 Gradle 任务；其他语言注册 python_test、node_build、cmake_build 等 command_id，绑定可执行文件、参数枚举和输出目录。禁止开放 npm run <任意文本> 或任意 shell 字符串。测试解析 JUnit XML 等机器格式优先，保留原始输出；用例失败、测试执行器异常和“没有运行任何测试”必须区分。

构建前记录源码快照、依赖锁与工具链版本，构建后记录退出码、产物路径与校验值。成功编译可以产生 APK，但不会因此自动安装或发布。warning 原文保留，告警数与错误数独立统计；已存在的测试失败也如实返回，不让 AGY 改测试以取得通过结果。

### 10.5 日志清洗与 shell

日志任务示例：“清洗指定构建日志，提取所有 error 与 warning，按原文和位置去重，保存完整索引，只返回前 20 组。”优先流式程序提取，再由 AGY 处理需要上下文的结构归纳。无需把 100 MiB 原始日志一次塞进模型；分块处理保留重叠窗口、源行号和全量计数。

shell 是最后开放的任务类型。每条 command_id 都绑定绝对可执行文件、可信脚本、参数 schema、cwd 和副作用范围。禁止 eval、动态命令拼接、任意 -Command、管道与命令替换。需要新命令模板时由 Codex 更新受保护配置，AGY 不能自建模板。代码生成、批量替换或格式化若改变源码，仍需 code_write 授权。

## 11 Windows 本地部署步骤

### 11.1 环境盘点

先读取项目 AGENTS.md、依赖文件及构建说明，检查 Windows 版本与虚拟化能力、磁盘、PowerShell 7、Python x64、Git、AGY、JDK/SDK/adb。不得因缺失某项而直接全局升级。JDK 与 Gradle/AGP 按项目已有组合选择，非 Android 项目不安装 Android 工具链。

```powershell
# 只读盘点；后续安装脚本同样使用 PowerShell 7。
Get-Command pwsh.exe, git.exe, agy.exe -ErrorAction SilentlyContinue
Get-Command py.exe, adb.exe, java.exe -ErrorAction SilentlyContinue
agy.exe --help
```

模型列表、登录与 hook 实验在隔离测试目录执行。安装者记录成功验证的版本与哈希，能力探针失败时明确报告，不自动换另一个 CLI 或降级旧协议。Python 依赖在 .venv 中安装；不要改用户全局包。

### 11.2 安装与注册

本地 AI 先实现 scripts/install.ps1、doctor.ps1、start.ps1、uninstall.ps1，所有脚本以 Win10 x64 和 pwsh.exe 为基准。install 创建 .venv、从锁文件安装应用、校验配置，默认不改全局执行策略、不自动添加管理员常驻服务。脚本若涉及账户或 ACL 配置，单独列出具体变更；Runtime 日常不以管理员运行。

完成隔离账户或 VM、工作区快照、输出目录 ACL 与私有通道配置。受限账户必须能够使用自己已登录的 AGY 身份；不能复制控制用户全部配置与密钥。Broker 仅开放所需能力；若使用 loopback HTTP，也须认证，不能认为 localhost 天然可信。默认禁止监听 0.0.0.0。

doctor 依次检查配置 schema、可执行文件、AGY 帮助、MCP 握手、临时 artifact、隔离写拒绝与允许动作、进程树终止，然后才启用真实项目。MCP Bridge 由 Codex 按 stdio 配置启动；启动日志不污染 stdout。Bridge 自动拉起的 Controller 使用无窗口后台进程，日志写入 data/logs。必须保留原 Codex 配置并只增加独立表。升级或卸载时先运行 scripts/stop.ps1，再替换代码或移除配置。

中文与空格路径、Unicode 提示词、CRLF 与非 UTF-8 构建日志都要实测。Python 子进程使用参数列表，不使用 shell=True；调用 .ps1 用固定 pwsh.exe -File 入口。日志按字节保存，解码生成派生文本。后台辅助进程如通过 Start-Process 启动，默认 -WindowStyle Hidden，并记录可精确清理的任务句柄。

### 11.3 Git 与工作区

Codex 在自己的分支或 worktree 修改；AGY 使用按任务准备的执行副本，避免双方同时编辑。worktree 只隔离工作目录，并不隔离用户权限、网络或共享 .git。严格 code_write=false 时，将执行副本的源码设为只读，允许明确输出目录。非 Git 项目用快照和哈希实现同样的输入追踪。

dirty 工作树要包含用户未提交改动，否则编译对象可能不是 Codex 刚修改的版本。Runtime 以清单同步，并记录输入快照；不得 reset --hard、清理未知文件或覆盖用户改动。AGY 获准改源时只在独立副本操作，产生 patch；Codex 审查后应用。Git 提交说明使用“英文类型: 中文内容”，例如 fix: 修复任务取消后的进程残留。

uninstall 只移除本服务注册、安装目录与所属进程；默认保留证据数据。删除数据必须明确指定已核对的目录，不能从环境变量推导后直接递归删除。服务停止及升级前先拒绝新任务，结束现有任务并完成审计。

## 12 分阶段实施与验收

### 阶段一 MVP 编译与日志闭环

交付六个 MCP API、单任务 Runtime、AGY 参数适配和事件解析、build/log Broker、基本强制权限、artifact 仓库、Windows 脚本及锁文件。先用失败编译 fixture 跑通，再运行真实项目。首轮不要求浏览器、Android 或任意 shell 可用。

验收：Codex 发起失败构建后得到文件、行列、任务和错误原文，无原因分析；按引用取到一致的日志片段；Codex 修改源码并续轮，编译成功。source_changed=false 与文件快照一致。拒绝源码写、越界读、未知命令、伪造任务 ID；取消后无所属构建残留。缺少强制拒绝机制时，MVP 不得被标记为完成。

### v0.3 多客户端生命周期验收

两个 stdio Bridge 可以同时 initialize 和 tools/list；A 提交的任务可由 B 查询、取消及读取 artifact。关闭任一或全部 Bridge 不停止 Controller 和任务。并发首次启动只产生一个 Controller；旧 endpoint 必须通过 health check 才可信。Controller 重启后，历史任务和 artifact 可读，重启时未结束的任务转为 interrupted 且不自动重做。

### 阶段二 浏览器

接入受支持环境中的 Playwright 与独立 profile，完善 origin、业务动作与网络范围。验收可完成一个测试站点流程，输出前后截图和 console/network 摘要；跨域跳转、未授权上传及页面提示注入不能扩大权限。

### 阶段三 Android

接入 adb 与必要的 UI 适配器，建立 serial/package 锁、截图、UI tree、Logcat 时间窗。验收指定设备流程成功；多设备缺 serial 被拒绝，未授权清数据/安装被拒绝，断连或应用崩溃仍能返回已有证据。

### 阶段四 视觉

验证 AGY 实际图片输入、OCR、比较与 bbox，按需返回裁剪图。验收已知文字和视觉差异、原图坐标映射、模糊图的不确定标记；大图不挤占默认结果，截图内的指令不会获得权限。

### 阶段五 增强权限与审计

在已有基础权限上完善更细粒度策略、并发隔离、授权撤销、短期 token、审计校验、保留与配额、网络策略及受控 shell。基本安全不是这一阶段才开始。验收 hook 被删、超时、伪造允许结果、工具间接调用、Windows 路径绕过等情形仍无法越权；重启后不重复有副作用的动作。

### 最终验收清单

1. 从全新安装环境按说明启动 MCP，六个工具可发现且 schema 校验有效。
2. AGY 每轮 PID 不同，续会话 ID 相同，workspace 不串用，源码快照准确。
3. 运行十万行日志样例时，默认响应仍受 16 KiB 上限约束，证据定位和总数正确。
4. 错误编译、AGY 登录失败、协议缺终态、磁盘满与取消分别得到正确状态。
5. code_write=false 时，原生写工具、shell 重定向、构建脚本及路径绕过均无法改源码。
6. code_write=true 仅允许明确路径，本轮结束后撤销，提交与推送仍不自动发生。
7. 浏览器和 Android 未授权业务动作被拒绝，截图、UI tree 与日志按需可取。
8. AGY 输出不能伪造退出码、权限或证据；提示注入不能改变控制策略。
9. 超时和 Runtime 退出能清理所属进程，其他项目的浏览器、Java 和 adb 不受影响。
10. 中文及空格路径、日志编码、留存清理与 Windows 10 x64 安装均有实测记录。

本地 AI 最终交付源码、依赖锁、脚本、配置示例、六个 API 的 schema、脱敏 fixtures、测试结果与部署说明。报告逐项列出已实现、已实测、尚不可用能力，不把设计示例写成部署成功。不要改成 AGY 自动修代码的代理，也不要绕开 MCP 让 Codex 直接消费全量原始日志。
